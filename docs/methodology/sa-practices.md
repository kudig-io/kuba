# SA 解决方案架构师实践（Solution Architect Practices）

SA（Solution Architect，解决方案架构师）是连接**厂商技术能力**与**客户业务目标**的桥梁角色。在故障复盘中，SA 视角回答两个核心问题：**故障如何冲击客户关系（客情危机）？故障暴露了哪些客户架构的技术风险（技术危机）？** 与 SRE 的"系统面"、CRE 的"客户感知面"互补，SA 聚焦"客户关系维护 + 客户架构赋能"。

## 1. 客情危机（Customer Relationship Crisis）

故障首先是**商业事件**，其次才是技术事件。SA 视角评估故障对客户关系的冲击与修复路径：

| 维度 | 说明 | 示例 |
|---|---|---|
| 信任冲击 | 故障对客户信任的损耗程度、是否引发舆情/监管关注 | Gmail 2008：8 个月 6 次中断动摇企业客户对云办公的信任 |
| 沟通与安抚 | 厂商是否主动联系关键客户、提供替代方案与恢复预估 | AWS 2011：官方 PES 详细披露根因，缓解客户恐慌 |
| 商业补偿 | SLA 豁免、服务额度、续约影响 | Salesforce 2019：权限事故后加强安全承诺以挽回企业客户 |
| 关系修复 | 故障后的客户回访、复盘分享、技术改进承诺 | 腾讯 2023：高管问责+公开复盘挽回国民级产品信任 |

**SA 行动准则**：故障期间主动触达关键客户（而非等待客户来问）；用客户业务语言解释影响（"您的支付链路受影响 2 小时"而非"内部组件异常"）；承诺的修复时间必须保守且持续兑现。

## 2. 技术危机（Technical Crisis）

故障对客户架构而言是**免费的架构评审**。SA 视角从每个故障中提炼对客户技术选型与架构设计的启示：

| 维度 | 说明 | 示例 |
|---|---|---|
| 架构启示 | 故障暴露的架构风险，客户应引以为戒 | Facebook 2021：单域名（facebook.com）权威 DNS 单一化的风险 |
| 客户侧自保 | 客户应具备的降级/切换/多活能力 | Dyn 2016：多 DNS 提供商成为标配 |
| 技术建议 | SA 应给出的可落地建议（重试策略、缓存、隔离） | AWS 2017：跨区域复制（CRR）与独立监控 |
| 选型教训 | 从故障中学到的技术选型教训（避免单点、避免强依赖） | CrowdStrike 2024：供应商客户端深度嵌入系统的风险 |

**SA 行动准则**：将供应商故障转化为客户架构改进的契机——主动向客户输出"该故障对您架构的三条启示"；帮助客户识别自身依赖链上的单点（域名、认证、DNS、第三方机房）；在售前方案中明确"故障模式与降级路径"。

## 3. SA 视角在案例中的落点

每个案例的 SA 视角提炼为两行结论，纳入 "SRE / CRE / FDE / SA 视角速览" 表格：

- **SA（客情危机）**：一句话概括故障对客户关系的冲击与厂商应对表现（信任、沟通、补偿、修复）。
- **SA（技术危机）**：一句话概括故障对客户架构的启示（单点风险、自保能力、选型教训）。

## 4. 四视角协同

| 视角 | 关注点 | 核心问题 |
|---|---|---|
| SRE | 系统与流程 | 系统为什么会失效？如何不再失效？ |
| CRE | 客户与信任 | 客户感知到了什么？沟通是否及时透明？ |
| FDE | 数据与证据 | 现场数据如何还原真相？ |
| **SA** | **关系与架构** | **故障如何冲击客户关系？客户架构该如何改进？** |
