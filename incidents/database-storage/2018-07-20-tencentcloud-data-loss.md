# 腾讯云数据丢失（2018-07-20）：三副本为什么没能救回创业公司的数据

## 摘要

2018 年 7 月 20 日，创业公司"前沿数控"在腾讯云上的云硬盘数据发生**永久性丢失**，其线上生产数据（含备份在同一云盘体系内）无法恢复，公司称近千万元估值的业务数据毁于一旦。腾讯云官方复盘披露的技术链条是：受影响云盘所在的物理仓**磁盘固件版本存在缺陷，发生了静默数据错误（silent data corruption）**——数据损坏但未被检测发现；随后运维在对该仓做数据搬迁时**连续两次违反标准操作规范**：第一次搬迁前未按规范打快照，第二次在源仓静默错误未排除的情况下，将数据校验环节遗漏，最终**三副本同时继承了损坏数据**，健康副本被回收，数据无法恢复。腾讯云公开致歉，承认"部分运维人员违规操作"，最终按合同赔付并额外补偿共计 **13.64 万元**——与用户主张的千万元损失形成巨大落差，引发了关于**云数据责任边界、SLA 赔偿上限与用户自建备份义务**的全行业大讨论。该案例是"三副本≠数据安全"的中文互联网第一课。

## 影响评估（CRE 视角）

- **影响面**：单一客户（前沿数控）生产数据永久丢失；同仓其他客户数据经排查未受影响
- **影响时长**：数据丢失不可逆（duration 记为 -1：非时间型故障）
- **次生影响**：SLA 赔偿上限 vs 实际业务损失的争议成为公共议题；推动国内用户跨云/离云备份意识觉醒
- **对外沟通评估**：复盘技术细节披露较充分（固件缺陷+违规操作链），但赔偿争议使舆论评价两极
- **定级依据**：影响单客户但数据永久丢失（最严重的故障后果类型），SEV-2
- 未披露信息：静默错误的具体固件型号、受影响数据量

## 技术细节与根因分析（SRE 视角）

### 背景架构

腾讯云 CBS 云硬盘采用三副本机制保障可靠性：正常情况下任一副本损坏可由其余副本修复。数据搬迁（仓间迁移）的标准流程要求：迁移前快照、迁移中数据校验、迁移后源数据延迟回收——三道防线分别对应"可回退、可发现、可挽救"。

### 因素三分

- **触发因素（Trigger）**：磁盘固件缺陷产生静默数据错误——数据已损坏但读取无报错。
- **根本原因（Root Cause）**：数据完整性防线全部失守——静默错误未被端到端校验发现，迁移流程的两道人工规范（快照、校验）又被违规跳过，三副本机制随迁移复制了坏数据并回收了好数据。
- **扩大因素（Aggravating Factors）**：
  1. 三副本是**可用性机制而非完整性机制**：副本间同步复制损坏数据毫无抵抗力；
  2. 客户的备份也在同一云盘体系内，无异构/离线备份；
  3. 高危迁移操作无强制自动化闸门，规范执行依赖人的自觉。

- **减轻因素（Mitigating Factor）**：仅影响单个客户（前沿数控）；腾讯云后续完善了磁盘静默错误检测机制。

### 5 Whys

```
现象：客户生产数据三副本全部损坏且不可恢复
Why1 → 迁移把静默损坏的数据复制到了新仓三副本，健康数据被回收
Why2 → 迁移前未打快照、迁移中未做数据校验（两次违规操作）
Why3 → 高危操作规范无系统强制（可跳过），依赖人工执行
Why4 → 磁盘固件缺陷导致的静默错误未被存储层端到端校验捕获
Why5 → 数据完整性体系假设"损坏必报错"，未按"静默损坏"设防
        （系统性原因：完整性校验缺位 + 高危操作防呆缺位的双重失守）
```

## 解决过程

腾讯云在客户报障后组织数据抢救，尝试从底层残留数据恢复未果，确认永久丢失。官方公告披露完整因果链并致歉，处理相关运维人员；赔偿按合同 SLA 上限及额外补偿合计 13.64 万元，客户不接受并公开维权，最终成为行业标志性争议案例。腾讯云整改包括：加装端到端数据校验、迁移类操作全流程系统化强制（快照/校验/延迟回收不可跳过）。

## 经验教训

1. **副本数量解决可用性，校验才解决完整性**：静默数据错误必须靠端到端校验（checksum 全链路）捕获，三副本、五副本都会忠实复制坏数据。
2. **高危操作规范必须系统强制**：能被人跳过的规范等于没有规范——快照、校验、延迟回收应是流程闸门而非操作建议（与 AWS ELB 2012 同款教训）。
3. **用户侧：云内备份不是备份**：同体系内的"备份"与生产共享同一故障域，关键数据必须异构介质/跨云/离线备份（3-2-1 原则）。
4. **SLA 赔偿上限与业务损失的巨大落差**是云计算商业模式的固有缺口——高价值数据的风险自留部分需要用户以备份与保险覆盖。
5. 静默错误是存储系统最阴险的敌人：**固件版本管理与巡检校验**（scrubbing）必须常态化。

## 预防与改进措施

- **预防（Prevent）**：全链路端到端校验；磁盘固件版本准入与缺陷跟踪
- **减小爆炸半径（Contain）**：迁移流程系统化强制（快照→校验→延迟回收），源数据延迟回收留出挽救窗口
- **快速检测（Detect）**：后台数据巡检（scrubbing）主动发现静默损坏
- **快速恢复（Recover）**：用户侧 3-2-1 备份；平台侧回收站/延迟删除机制
